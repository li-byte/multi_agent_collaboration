## 1. PostgreSQL 表设计

### 1.1 表分组

| 分组 | 表 | 归属 |
| --- | --- | --- |
| 权威事实层 | `evidence` | 自建，启动时由 mock 数据灌入，**只读** |
| 一致性账本 | `agent_run` / `agent_task` / `finding` / `agent_event` | 自建，运行期读写 |
| 图状态持久化 | `checkpoints` / `checkpoint_blobs` / `checkpoint_writes` / `checkpoint_migrations` | 由 `AsyncPostgresSaver.setup()` 自动创建 |

> ⚠️ LangGraph 的 checkpoint 表由库自己建。手动传连接时必须 `autocommit=True` + `row_factory=dict_row`，否则 `.setup()` 不落库、读取会报 `TypeError`。
> 推荐直接用 `AsyncPostgresSaver.from_conn_string(DSN)`（内部已处理）。

### 1.2 DDL（`schema.sql`）

```sql
-- ============================================================
-- 多 Agent 协作一致性演示 · 建表脚本
-- 目标库：agents @ 192.168.10.101:5432
-- 说明：LangGraph 自身 checkpoint 表由 AsyncPostgresSaver.setup() 创建，此处不含
-- ============================================================

-- ---------- ① 权威事实层：Agent 只能引用，不能改写 ----------
CREATE TABLE IF NOT EXISTS evidence (
    evidence_id  TEXT PRIMARY KEY,            -- 如 'slowlog#14:32'
    kind         TEXT        NOT NULL,        -- slow_query / metric / deploy / config
    source       TEXT        NOT NULL,        -- 来源系统名
    ref_version  TEXT        NOT NULL,        -- commit-a / commit-b / none
    occurred_at  TIMESTAMPTZ NOT NULL,        -- 证据发生时间
    summary      TEXT        NOT NULL,        -- 一句话摘要（给 LLM 看）
    content      JSONB       NOT NULL,        -- 原始明细
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_evidence_time ON evidence(occurred_at);

-- ---------- ② 全局任务 ----------
CREATE TABLE IF NOT EXISTS agent_run (
    global_task_id UUID        PRIMARY KEY,
    title          TEXT        NOT NULL,
    alert          JSONB       NOT NULL,
    snapshot       JSONB       NOT NULL,      -- 事实锚点：{repo, commit, time_window}
    status         TEXT        NOT NULL,      -- created/planning/researching/executing/reviewing/done/failed
    round          INT         NOT NULL DEFAULT 0,
    version        INT         NOT NULL DEFAULT 0,   -- 乐观锁
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- ---------- ③ 子任务 / 角色执行记录 ----------
CREATE TABLE IF NOT EXISTS agent_task (
    global_task_id  UUID        NOT NULL REFERENCES agent_run(global_task_id) ON DELETE CASCADE,
    sub_task_id     TEXT        NOT NULL,
    attempt         INT         NOT NULL DEFAULT 1,
    role            TEXT        NOT NULL,     -- planner/researcher/executor/reviewer
    agent_id        TEXT        NOT NULL,     -- 逻辑执行者标识
    status          TEXT        NOT NULL,     -- pending/running/completed/failed/unknown
    version         INT         NOT NULL DEFAULT 0,
    lease_until     TIMESTAMPTZ,              -- 租约到期时间
    input_snapshot  JSONB       NOT NULL,     -- 本次执行基于的快照（防串版本）
    evidence_refs   JSONB       NOT NULL DEFAULT '[]'::jsonb,
    result_ref      TEXT,                     -- 产物引用
    idempotency_key TEXT        UNIQUE,       -- run:sub_task:action
    error           TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (global_task_id, sub_task_id, attempt)
);
CREATE INDEX IF NOT EXISTS idx_task_run ON agent_task(global_task_id, created_at);

-- ---------- ④ 结论：候选 / 已验证 / 冲突 / 已否决 ----------
CREATE TABLE IF NOT EXISTS finding (
    finding_id     TEXT        PRIMARY KEY,
    global_task_id UUID        NOT NULL REFERENCES agent_run(global_task_id) ON DELETE CASCADE,
    sub_task_id    TEXT        NOT NULL,
    round          INT         NOT NULL DEFAULT 0,
    claim          TEXT        NOT NULL,
    status         TEXT        NOT NULL,      -- 候选/已验证/冲突/已否决
    evidence_refs  JSONB       NOT NULL DEFAULT '[]'::jsonb,
    assumptions    JSONB       NOT NULL DEFAULT '[]'::jsonb,
    artifact_refs  JSONB       NOT NULL DEFAULT '[]'::jsonb,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_finding_run ON finding(global_task_id, created_at);

-- ---------- ⑤ 事件账本：前端时间线的唯一数据源 ----------
CREATE TABLE IF NOT EXISTS agent_event (
    seq              BIGSERIAL   PRIMARY KEY,
    global_task_id   UUID        NOT NULL REFERENCES agent_run(global_task_id) ON DELETE CASCADE,
    role             TEXT        NOT NULL,
    event_type       TEXT        NOT NULL,    -- run_created/node_start/node_end/handoff/finding/consistency/review/status/done/error
    snapshot_version INT         NOT NULL,
    round            INT         NOT NULL DEFAULT 0,
    evidence_refs    JSONB       NOT NULL DEFAULT '[]'::jsonb,
    payload          JSONB       NOT NULL,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_event_run ON agent_event(global_task_id, seq);
```

### 1.3 幂等与租约的落地规则

| 规则 | 具体做法 |
| --- | --- |
| 幂等键格式 | `{global_task_id}:{sub_task_id}:{action}`，`UNIQUE` 约束兜底 |
| 认领（防重复） | `UPDATE agent_task SET status='running', lease_until=now()+interval '5 min', version=version+1 WHERE global_task_id=$1 AND sub_task_id=$2 AND attempt=$3 AND status='pending' RETURNING *` —— 影响行数为 0 即认领失败 |
| 接管 | 仅当 `lease_until < now()` 且状态仍为 `running` 时允许新执行者接管 |
| 过期写入拒绝 | 更新时带 `AND version = $expected`，影响行数 0 ⇒ 判定为过期消息并丢弃 |
| 状态未知 | `status='unknown'` ⇒ 先查远端真实状态，**不盲目重放** |

## 2. 状态契约（Pydantic，直接用于代码）

### 2.1 公共类型

```python
from typing import Literal, TypedDict, Annotated
import operator
from pydantic import BaseModel, Field

ResultStatus = Literal["候选", "已验证", "冲突", "已否决"]
RunStatus    = Literal["created", "planning", "researching", "executing",
                       "reviewing", "done", "failed"]
TaskStatus   = Literal["pending", "running", "completed", "failed", "unknown"]


class Snapshot(BaseModel):
    """事实锚点：全链路冻结，任何产物都必须标注它。"""
    repo: str
    commit: str
    time_window: tuple[str, str]
```

### 2.2 四个角色的输出契约

```python
# ---------- Planner ----------
class SubTask(BaseModel):
    sub_task_id: str = Field(description="稳定且唯一的子任务 ID，如 st-1")
    title: str
    depends_on: list[str] = Field(default_factory=list, description="依赖的子任务 ID")
    parallelizable: bool = True
    inputs_required: list[str] = Field(default_factory=list,
                                       description="需要哪些输入/证据才能开始")

class PlannerOutput(BaseModel):
    plan_reason: str = Field(description="为什么这样拆：说明依赖关系与并行边界")
    sub_tasks: list[SubTask]


# ---------- Researcher ----------
class Finding(BaseModel):
    claim: str = Field(description="一句可核对的主张，例如：orders 表缺索引导致全表扫描")
    status: ResultStatus = "候选"
    evidence_refs: list[str] = Field(description="必须引用证据源中真实存在的 evidence_id")
    assumptions: list[str] = Field(default_factory=list, description="仍在猜的部分")

class ResearcherOutput(BaseModel):
    findings: list[Finding]


# ---------- Executor ----------
class AcceptanceItem(BaseModel):
    item_id: str
    statement: str
    evidence_refs: list[str] = Field(description="该项验收所依据的证据，不能为空")

class Artifact(BaseModel):
    artifact_id: str
    based_on_commit: str = Field(description="本次修复基于的 commit，必须等于 snapshot.commit")
    covers_time_window: tuple[str, str] = Field(description="修复覆盖的时间窗")
    changes: list[str] = Field(description="具体改动，逐条列出")
    evidence_refs: list[str] = Field(description="本次修复依据的 finding 证据")
    acceptance: list[AcceptanceItem] = Field(description="怎样算修好，逐条 + 证据")
    verify_command: str = Field(description="可执行的自检命令，禁止只写『已完成』")

class ExecutorOutput(BaseModel):
    artifact: Artifact


# ---------- Reviewer ----------
class ReviewCheck(BaseModel):
    check_id: str
    target: str
    result: Literal["pass", "fail"]
    evidence_ref: str | None = None
    note: str = ""

class ReviewerOutput(BaseModel):
    decision: Literal["approve", "veto"]
    checks: list[ReviewCheck]
    blockers: list[str] = Field(default_factory=list)
    reason: str
    rework_target: Literal["researcher", "executor"] | None = None
```

### 2.3 一致性校验报告

```python
class InvariantResult(BaseModel):
    invariant_id: str          # V1_snapshot_pinned ...
    title: str
    result: Literal["pass", "fail"]
    detail: str = ""
    offenders: list[str] = Field(default_factory=list)

class ConsistencyReport(BaseModel):
    passed: bool
    results: list[InvariantResult]
```

### 2.4 LangGraph 共享状态（交接对象）

```python
class TaskState(TypedDict, total=False):
    global_task_id: str
    snapshot: dict                 # Snapshot.model_dump()
    status: str                    # RunStatus
    version: int
    round: int
    sub_tasks: list[dict]          # PlannerOutput.sub_tasks
    findings: list[dict]           # 累积的 Finding
    artifacts: list[dict]          # 累积的 Artifact
    consistency: dict              # ConsistencyReport.model_dump()
    review: dict                   # ReviewerOutput.model_dump()
    events: Annotated[list[dict], operator.add]   # 节点追加 → SSE
```

> `events` 用 `operator.add` reducer，保证多节点写入时是**追加**而非覆盖（LangGraph 惯用法）。

## 3. SSE 事件协议

端点：`GET /api/runs/{global_task_id}/stream`
Content-Type：`text/event-stream`；客户端断线自动重连并带 `Last-Event-ID`（内容为 `seq`）。

| `event` | 何时发 | `data` 结构要点 |
| --- | --- | --- |
| `hello` | 建立连接 | `{"global_task_id","status","version"}` |
| `run_created` | 创建任务 | `{"snapshot":{...}}` |
| `node_start` | 节点开始 | `{"seq","role","round","snapshot_version"}` |
| `node_end` | 节点结束 | `{"seq","role","ok","summary","version"}` |
| `handoff` | 交接发生 | `{"from","to","handoff":{snapshot,evidence_refs,assumptions,acceptance}}` |
| `finding` | 产出结论 | `{"finding_id","claim","status","evidence_refs","assumptions"}` |
| `artifact` | 产出修复 | `{"artifact_id","based_on_commit","covers_time_window","acceptance"}` |
| `consistency` | 校验完成 | `{"passed":false,"results":[{"invariant_id":"V4","result":"fail",...}]}` |
| `review` | 评审结论 | `{"decision":"veto","blockers":[...],"rework_target":"researcher"}` |
| `status` | 状态推进 | `{"status","version","round"}` |
| `done` | 全流程结束 | `{"status":"done","round","reason"}` |
| `error` | 异常 | `{"where","message"}` |

**示例流**（一次含否决的完整链路）：

```
event: node_start
data: {"seq":1,"role":"planner","round":0,"snapshot_version":0}

event: node_end
data: {"seq":2,"role":"planner","ok":true,"summary":"拆解出 4 个子任务","version":1}

event: handoff
data: {"from":"planner","to":"researcher","handoff":{"snapshot":{"commit":"commit-b"},"evidence_refs":[],"assumptions":[],"acceptance":[]}}

event: finding
data: {"finding_id":"f-1","claim":"orders 表缺索引导致全表扫描","status":"候选","evidence_refs":["slowlog#14:32","pgstat#14:35"],"assumptions":["索引未随发布回滚"]}

event: consistency
data: {"passed":false,"results":[{"invariant_id":"V4_artifact_cites_findings","title":"artifact 必须引用依据的 finding 证据","result":"fail","detail":"artifact#1 未解释 15:35 之后的连接池指标","offenders":["pgstat#15:35"]}]}

event: review
data: {"decision":"veto","blockers":["修复未覆盖 15:20 之后的连接池排队"],"rework_target":"researcher","reason":"acceptance 第 3 项无证据支撑"}

event: status
data: {"status":"researching","version":2,"round":1}

event: done
data: {"status":"done","round":1,"reason":"reviewer approve 且校验器全绿"}
```

## 5. 内置证据源（`app/mock_data.py`）

### 5.1 设计原则

1. **确定性**：不用随机数，同一任务每次跑出的证据完全一致。
2. **带版本**：每条证据都有 `ref_version`（`commit-a` / `commit-b`），让"基于哪一版"可判定。
3. **带时间**：`occurred_at` 让"时间窗覆盖"可判定。
4. **可追溯**：`content` 存原始明细，前端点击 chip 能展开看到"原文"。
5. **两段根因**：14:00–15:20 是索引问题，15:20 之后是连接池问题 —— 这是稳定触发否决的数据基础。

### 5.2 数据定义（骨架）

### 5.3 演示模式（`DEMO_MODE=on`）

为保证每次演示都能看到"否决 → 回流"：

- 第 1 轮：证据源**只暴露 14:00–15:20 的证据**给 Researcher（模拟"只查了前半段"）。
- Executor 据此产出只针对 `orders` 索引的修复，`covers_time_window = ["14:00","15:20"]`。
- 校验器 `V1`（时间窗未覆盖 snapshot）与 `V5`（验收项缺证据）**必然 fail** → 强制 veto。
- 回流后 Researcher 拿到完整证据 → 第二轮通过。

> 该模式下"否决"由数据与不变量确定性触发；关掉 `DEMO_MODE` 则完全交给 LLM 自由发挥。

## 6. 关键 SQL（实现时直接复用）

```sql
-- 认领子任务（防重复 + 租约）
UPDATE agent_task
   SET status='running', lease_until = now() + interval '5 minutes',
       version = version + 1, updated_at = now()
 WHERE global_task_id = %(run)s AND sub_task_id = %(sub)s AND attempt = %(att)s
   AND status = 'pending'
RETURNING *;

-- 版本受控更新（拒绝过期消息）
UPDATE agent_run
   SET status = %(status)s, version = version + 1, updated_at = now()
 WHERE global_task_id = %(run)s AND version = %(expected)s
RETURNING version;

-- 幂等写入（重复执行不产生第二份副作用）
INSERT INTO agent_task (global_task_id, sub_task_id, role, agent_id, status,
                        input_snapshot, idempotency_key)
VALUES (%(run)s, %(sub)s, %(role)s, %(agent)s, 'pending', %(snap)s, %(key)s)
ON CONFLICT (idempotency_key) DO NOTHING
RETURNING *;

-- 时间线重建（前端刷新/历史回放）
SELECT seq, role, event_type, snapshot_version, round, evidence_refs, payload, created_at
  FROM agent_event WHERE global_task_id = %(run)s ORDER BY seq;
```

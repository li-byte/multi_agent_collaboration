## 2. 依赖清单

### 2.1 `requirements.txt`

```txt
# ---------- Agent 编排（要求 1.x）----------
langgraph>=1.0,<2.0
langgraph-checkpoint-postgres>=2.0
langchain>=1.0,<2.0
langchain-core>=1.0,<2.0
langchain-openai>=1.0,<2.0

# ---------- Web 服务 ----------
fastapi>=0.115
uvicorn[standard]>=0.30
sse-starlette>=2.1

# ---------- 数据库（Psycopg 3，PostgresSaver 必需）----------
psycopg[binary,pool]>=3.2

# ---------- 配置与校验 ----------
pydantic>=2.9
pydantic-settings>=2.5
python-dotenv>=1.0
```

> **说明**
> - `langgraph-checkpoint-postgres` 默认只装 `psycopg` 核心，必须显式加 `[binary]` 才能免编译安装。
> - DeepSeek 走 OpenAI 兼容协议，用 `langchain-openai` 的 `ChatOpenAI` + `base_url` 即可，不额外引入 SDK。
> - 不引入 LangSmith / 前端构建链，保持轻量。

### 2.2 关键 API 用法（已核对官方文档）

```python
# 图定义
from langgraph.graph import StateGraph, START, END

# 持久化（异步）
from langgraph.checkpoint.postgres.aio import AsyncPostgresSaver

async with AsyncPostgresSaver.from_conn_string(DSN) as saver:
    await saver.setup()          # 首次运行建表，只需一次
    graph = builder.compile(checkpointer=saver)
    config = {"configurable": {"thread_id": global_task_id}}
    async for chunk in graph.astream(state, config, stream_mode="updates"):
        ...
```

> 手动传连接时必须 `autocommit=True` + `row_factory=dict_row`，否则 `.setup()` 不落库、读取报 `TypeError`。
> 建议直接使用 `from_conn_string`，内部已处理这两项。

```python
# 结构化输出（保证每个角色产出可校验的契约）
from langchain_openai import ChatOpenAI
llm = ChatOpenAI(model=settings.deepseek_model,
                 api_key=settings.deepseek_api_key,
                 base_url=settings.deepseek_base_url,
                 temperature=0)
planner = llm.with_structured_output(PlannerOutput)
```

## 5. 演示脚本（分镜）

> 目标：**5 分钟内讲清"多 Agent 如何保持一致"**。

### 分镜 0 · 开场（20s）

打开首页，指出顶部信息条：

> "这条链路从头到尾只认**一个快照**：`commit-b` + 时间窗 `14:00–16:00`。
> 所有 Agent 的产物都必须标注它 —— 这就是'同一份事实'。"

### 分镜 1 · 创建任务，看 Planner 拆解（40s）

点「新建排查任务」，表单已预填 `user-service` 告警。启动后第一张卡出现：

> "Planner 拆出 4 个子任务，每个都写了**依赖**和**需要什么输入**。
> 拆解不是把任务复制几份发出去 —— 这里能看到哪些可并行、哪些必须等。"

**指向**：卡片上的 `sub_tasks` + `depends_on`。

### 分镜 2 · Researcher 交接（60s）

Researcher 卡片出现，带 `候选` 徽标与证据 chip：

> "Researcher 说'orders 表缺索引'。但注意 —— 它交出去的不是这句话，
> 而是一份**带来源的工作状态**：快照版本、证据引用、还在猜的假设。"

**指向**：右侧「共享状态」面板，切换 showing `snapshot / findings / assumptions / acceptance`。

> "聊天记录是历史，摘要只是当前工作集的一部分，代码库和指标才是权威事实。
> 我们的结论必须能点回到原始证据。"

**动作**：点 `slowlog#14:32` chip → 底部抽屉展示原始 SQL 与执行计划。

### 分镜 3 · Executor 产出（40s）

Executor 卡片出现：

> "Executor 产出 artifact，必须写清三件事：**基于哪一版**、**覆盖哪个时间窗**、
> **怎样算修好**。看这里的 acceptance —— 每一项都要带证据，不许只写'已完成'。"

**指向**：`based_on_commit` / `covers_time_window` / `acceptance`。

### 分镜 4 · 🔴 关键：Reviewer 否决与回流（90s）

Reviewer 卡片标红 `VETO`，出现**红色回流箭头 + `v1 → v2`**：

> "真正的重点在这里。请注意发生了什么：
> ① 校验器发现 artifact **只覆盖了 14:00–15:20**，解释不了 15:35 的连接池指标；
> ② 运行时**强制**把 ReviewResult 改成 veto，即使模型想说 approve 也不允许；
> ③ veto **改变了后续路由** —— 任务退回 Researcher，version +1、round +1。
> 如果审查改变不了后续动作，它就只是一条评论，不是系统的一部分。"

**动作**：打开右栏「一致性校验」面板，逐条念 7 条不变量：

> "V1 快照锚定 ✅、V2 证据真实存在 ✅、V3 结论有证据 ✅、
> **V4 产物引用依据的证据 ❌**、**V5 验收项都有证据 ❌**、V6 版本单调 ✅、V7 幂等键 ✅。
> 这就是'模型负责判断，运行时负责证明'。"

### 分镜 5 · 回流后通过（40s）

第二轮 Researcher 补上 `pgstat#15:35` / `config#15:20`，Executor 改出覆盖全窗的修复，
Reviewer 变绿 `APPROVE`，顶栏状态走到 `done`：

> "同一套状态推进到终态。注意 —— 完成不是一个句号，是状态机里的一个状态。"

### 分镜 6 · 账本收尾（40s）

打开右栏「账本表」：

> "最后回到工程本质。这张表回答四个问题：
> **谁在做**（role/agent_id）、**做到哪一步**（status/version）、
> **基于哪一版**（input_snapshot）、**试过几次**（attempt/lease_until/idempotency_key）。
> 带副作用的动作重复一次就可能产生脏数据 —— 所以重试落在子任务层，写操作带幂等键，
> 租约过期才允许接管，状态未知先去查远端，而不是盲目重放。"

### 收尾金句

> "多 Agent 没有绕开分布式系统的老问题，只是把执行者从服务和线程换成了会自主判断的 Agent。
> 推理可以有分歧 —— 但这个系统里**协议不能含糊**。"

## 7. 验收清单

### 功能
- [ ] 四角色按 `planner → researcher → executor → reviewer` 顺序执行
- [ ] 首次运行会经历 **veto → 回流 → 重做 → approve**
- [ ] 前端时间线**实时**出现卡片，无需刷新
- [ ] 证据 chip 可点击，展开原始证据明细
- [ ] 历史 run 可回放（从 `agent_event` 重建时间线）

### 一致性（核心）
- [ ] 每张卡片都标注 `基于 vN`，且全部等于 run 的 snapshot
- [ ] `V2` 能拦截 LLM 编造的证据 ID（可手工在提示词里诱导验证）
- [ ] 校验器 fail 时，LLM 的 `approve` 被**强制改写**为 `veto`
- [ ] veto 会改变路由与 `version`，不是只记一条日志
- [ ] `agent_task` 中 `attempt` / `lease_until` / `idempotency_key` 有实际值
- [ ] 重复触发同一 `idempotency_key` 不产生第二条记录

### 工程
- [ ] `python --version` 为 3.10.x
- [ ] `pip show langgraph langchain` 均 ≥ 1.0
- [ ] `.env` 已在 `.gitignore` 中
- [ ] 断网时 `LLM_MODE=mock` 仍能演示完整界面链路

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `TypeError: tuple indices must be integers` | 手动传连接缺 `row_factory=dict_row` | 用 `from_conn_string`，或补 `autocommit=True, row_factory=dict_row` |
| `.setup()` 后仍无 checkpoint 表 | 缺 `autocommit=True` | 同上 |
| `remove .venv` 报文件占用 | PyCharm 正在使用 | 关闭 PyCharm 后重试，或改用 `.venv310` |
| DeepSeek 返回 401 | key 过期 / base_url 少写 | 核对 `.env`；base_url 用 `https://api.deepseek.com` |
| `with_structured_output` 频繁失败 | 模型未按 schema 输出 | 降 `temperature`、在提示词里给出字段示例、失败重试 1 次后回落为"候选"结论 |
| 演示时没有出现否决 | 未开 `DEMO_MODE` | 设 `DEMO_MODE=on`，由数据与不变量确定性触发 |

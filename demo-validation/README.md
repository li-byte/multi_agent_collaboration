# 通用多智能体协作 · 一致性验证

> 🧊 **本目录已冻结（2026-09-15）** —— 验证已通过，不再修改。
> 冻结说明与验证结论见 **`FROZEN.md`**。

用 **LangGraph 1.x + LangChain 1.x** 搭的多智能体协作系统：**用户问一个问题、给一份资料，四个智能体协作，返回一个答案。**

重点是**协作过程的一致性**——把它变成可运行、可观察、可校验的代码：

> **同一个任务 · 同一份事实 · 同一套状态**
> 推理可以有分歧，协议不能含糊。
> **模型负责判断，运行时负责证明。**

**没有任何行业限定**：健康、代码、法律、任何领域都行。
系统不关心你问什么，只要求一件事 —— **结论必须引用你提供的原文，且逐字命中**。

---

## 1. 它做什么

```
用户：我血压 145/92，需要吃降压药吗？
      （附上一段医学资料原文）
  ↓
规划器  拆成 3 个子问题
研究员  逐个子问题查资料，给出结论 + 原文摘录
执行器  汇总成答案，每个分点带依据
审查器  核对 + 运行时一致性校验
  ↓
返回：一句话结论 + 分点论述 + 建议 + 资料不足之处（每条都能点回原文）
```

**没有资料就不干活**：如果你只问了问题没给资料，系统会先问你补资料 ——
因为「引用依据必须真实存在」是这个系统唯一的硬约束。

## 2. 快速开始

### 2.1 环境（Python 3.10）

```powershell
cd E:\pycharm_python_project\multi_agent_collaboration
Remove-Item -Recurse -Force .venv          # 先关掉 PyCharm
D:\Python310\python.exe -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -r requirements.txt
```

> 我已经用 `D:\Python310\python.exe` 建好一个装齐依赖、验证跑通的 **`.venv310`**，
> 想省事可以直接用它。

### 2.2 配置

`.env` 已写好（PG + DeepSeek）。关键开关：

| 变量 | 说明 |
| --- | --- |
| `LLM_MODE` | `deepseek` 真实调用；`mock` 离线兜底（不烧 token） |
| `STRUCTURED_METHOD` | 默认 `function_calling`。**DeepSeek 不支持 `response_format: json_schema`** |
| `USE_CHECKPOINTER` | `on` 挂 LangGraph Postgres checkpoint |
| `MAX_ROUNDS` | 回流轮次上限，兜底防死循环 |

### 2.3 初始化 + 启动

```powershell
python scripts\init_db.py            # 首次；表结构变了用 --reset
python run_server.py                 # → http://127.0.0.1:8000
```

> ⚠️ **不要用 `uvicorn app.server:app`**。uvicorn 在 Windows 上会显式选用
> `ProactorEventLoop`，而 psycopg 异步只能跑 `SelectorEventLoop`。
> `run_server.py` 自己拿循环直接 `serve()`，绕开这个坑。

### 2.4 三个自检脚本

```powershell
python scripts\check_contracts.py    # 13 项：契约适配 + 引用逐字校验
python scripts\run_cli.py            # 命令行跑完整链路
python run_server.py                 # 另开终端
python scripts\check_web.py --base http://127.0.0.1:8000   # 14 项：REST + SSE 端到端
```

## 3. 界面

对话式。你说一句话，四个智能体轮流「发言」；缺资料时先追问。

```
我：我血压 145/92，需要吃降压药吗？

系统：需要补充资料
      我的结论必须引用你提供的资料 —— 请把相关的原文贴进来。
      任何行业都行（健康、代码、法律…），系统只引用你给的资料，不会自己编。

我：📄 资料已提供（452 字，点击展开）

系统：已收到资料 5 段，开始协作

规 规划器
   我拆成 3 个子问题：st-1 … / st-2 … / st-3 …

   ┄┄ 规划器 → 研究员：交接 3 个子问题 ┄┄

研 研究员
   [已验证] [st-1] 资料 D1-1 提到：高血压的诊断标准…    ⟨D1-1⟩

   ┄┄ 研究员 → 执行器：交接 1 条结论 · 覆盖 1 个子问题 · 引用 1 段原文 ┄┄

执 执行器
   根据你提供的资料：…
   [st-1] …            ⟨D1-1⟩
   ▽ 验收条件 1 条

审 审查器 ✕ 不通过
   ▽ 运行时一致性校验 · 1 条失败：V6_subtask_coverage
   ↺ 退回研究员 · 版本 1 → 2 · 进入第 2 轮

研 研究员（第 2 轮）· 覆盖 3 个子问题
执 执行器（第 2 轮）· 覆盖 3 个子问题
审 审查器 ✓ 通过 · 8 条不变量全部 pass

系统：完成 · 共 2 轮
      [查看时序图] [一致性校验] [资料原文] [账本]
```

- **`⟨D1-2⟩` 是引用 chip** —— 点一下弹出资料原文，并把被引用的那句话**高亮**出来
- **交接条**（虚线胶囊）写明「谁把什么交给了谁」，这就是「传的是工作状态，不是聊天记录」
- 右上的四个按钮：📄 资料 / 📊 时序图 / 🔍 一致性校验 / 📒 账本

## 4. 一致性是怎么落地的

### 4.1 三对齐（通用版没有快照）

| 对齐目标 | 载体 |
| --- | --- |
| **同一个任务** | `global_task_id` + `sub_task_id`，认领用租约，幂等键防重复 |
| **同一份事实** | 用户提供的资料片段（权威事实层）+ **引用必须逐字命中原文** |
| **同一套状态** | 共享 `TaskState` + `version` 单调递增，旧消息不覆盖新状态 |

> 这里的「同一份事实」不是代码版本、也不是时间窗，而是**用户给的原文**。
> 所以任何行业都适用 —— 系统只证明「这句话确实来自你给的资料」。

### 4.2 八条不变量（`app/validators.py`）

全部是**确定性推导**，不看模型的自我声明：

| ID | 不变量 | 违反后果 |
| --- | --- | --- |
| V1 | 答案的每个分点都要有原文依据，**或显式声明资料不足** | 否决回流 |
| **V2** | **引用的摘录必须能在资料里逐字找到** | 否决回流（**防编造**） |
| V3 | 每条研究结论都要有原文依据，**或显式声明资料不足** | 否决回流 |
| V4 | 答案只能引用研究结论引用过的资料片段 | 否决回流 |
| V5 | 每条验收条件都要有原文依据，**或显式声明资料不足** | 否决回流 |
| **V6** | **拆出的每个子问题都要有答案覆盖** | 否决回流 |
| V7 | 状态版本必须被推进过 | 丢弃过期写入 |
| V8 | 所有执行记录必须带幂等键 | 拒绝执行 |

> **「声明资料不足」必须是显式的**：沉默和编造都不行，但「这份资料答不了这个问题」
> 是一条合法的出路 —— 否则系统永远无法诚实地回答「我不知道」。

### 4.3 引用是「哪份资料 + 哪句原文」

```python
class Citation(BaseModel):
    source_id: str   # D1-2 = 第 1 份资料的第 2 段
    quote: str       # 原文摘录，必须逐字一致
```

运行时把 `quote` 去掉空白后去资料里做**字符串匹配**，找得到才算数。于是：

| 防线 | 抓什么 | 靠什么 | 确定性 |
| --- | --- | --- | --- |
| **校验器 V2** | 编造原文 / 引用不存在的资料 | 字符串逐字匹配 | ✅ 确定性 |
| **审查器** | 曲解原文 / 依据不支持结论 | 回到原文核对语义 | ⚠️ 模型判断 |

这正好说明为什么两样都需要：**运行时能证明「引用是真的」，证明不了「引用支持这个结论」**。

### 4.4 硬门禁

```python
if not report.passed and out.decision == "approve":
    out = ... 强制改成 veto ...   # 模型的 approve 一律无效
```

只要有一条不变量 fail，审查器**不得** approve。界面上会标「运行时强制否决」。

### 4.5 回流什么时候发生

**完全取决于模型的真实表现**，没有任何人为注入。

系统只做一件事：如果研究结论漏掉了某个子问题、或者答案里出现了没有依据又没有声明「资料不足」的分点，
运行时校验就会 fail → 审查器被强制否决 → 退回研究员补查 → 版本 +1、进入下一轮。

真实运行里它会自然发生在这几种情况：

- 规划器把问题拆得很细，研究员第一次只答了一部分
- 模型第一次给出的摘录改写了原文（不是逐字复制），V2 判否
- 答案漏掉了某个子问题（V6）
- 答案引用了研究没查过的资料片段（V4）

**实测结果**（`mock` 离线模式，两个真实场景）：

```
场景 A  资料覆盖了问题            → 1 轮通过，12 条引用全部逐字命中，0 次否决
场景 B  资料答不上这个问题        → 1 轮通过，0 条引用，3 个分点显式声明「资料不足」
```

两个场景都不编造、都不漏答，各自给出了它该给的答案。

```
│   ├── runtime.py                # 事件总线 + 运行时上下文

│   └── server.py                 # FastAPI + SSE
├── web/index.html                # 对话式单页

    ├── init_db.py                # 建表（--reset 重建）
    ├── run_cli.py                # 命令行跑一次

    └── check_web.py              # REST + SSE 端到端自检
```

### 数据库表

| 表 | 作用 |
| --- | --- |
| `agent_run` | 任务：问题 + 状态 + 乐观锁 version |
| `source_chunk` | **权威事实层**：用户提供的资料片段，只读不改 |
| `agent_task` | 执行记录：role / attempt / status / lease_until / idempotency_key |
| `finding` | 结论：候选 / 已验证 / 冲突 / 已否决 + 引用 |
| `agent_event` | 事件账本，前端时间线的唯一数据源（SSE 可回放） |
| `checkpoints` 等 | LangGraph 自动创建，图状态持久化 |

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| `Psycopg cannot use the 'ProactorEventLoop'` | 用 `python run_server.py`，不要用 `uvicorn app.server:app` |
| 表结构报错 / 字段不存在 | `python scripts\init_db.py --reset` |
| DeepSeek 400 `response_format` | 保持 `STRUCTURED_METHOD=function_calling` |
| 不想烧 token / 没网 | `LLM_MODE=mock`，行为与真实模式一致 |
| 没看到否决回流 | 这是正常的 —— 回流只在模型真的漏答/改写引用时发生，没有人为注入 |
| 引用总被判编造 | 提示词已要求「逐字复制」，真实模型偶尔会改写标点；这正是 V2 存在的意义 |
| 控制台中文乱码 | `$env:PYTHONIOENCODING='utf-8'` |

## 7. 演示讲解顺序（5 分钟）

1. 先不贴资料直接提问 → 系统**追问资料**（这就是「依据必须真实存在」的第一道门）
2. 贴上资料 → 四个智能体依次「发言」
3. 点开一个引用 chip → **原文高亮**，证明结论确实来自你给的资料
4. 打开「一致性校验」→ 8 条不变量逐条通过
5. 打开「时序图」→ 看清「谁把什么交给了谁」
6. （可选）贴一段**答不上问题**的资料 → 它会显式说「资料不足」，而不是编一个答案

> 收尾：技术选型可以不同，边界不能空着。
> 模型负责判断，运行时负责证明。

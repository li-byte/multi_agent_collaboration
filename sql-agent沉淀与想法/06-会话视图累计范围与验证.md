# 当前会话全部轮次的视图与消耗统计

日期：2026-10-08。

## 展示范围

统一口径为当前 `conversation_id` 下全部任务：

| 组件 | 改造后行为 |
| --- | --- |
| 协作时序图 | 保留全部轮次事件，按问题分段，修正轮次与对话轮次分开 |
| 数据流转 | 每轮保留独立起点，HTML 导出覆盖全部事件 |
| 顶栏消耗 | 当前会话累计调用与 token，获取账本后优先显示账本汇总 |
| 消耗清单 | 包含全部调用，保留任务 ID、对话轮次、修正次数与子任务游标；PNG 导出同口径 |
| SQL 审计 | 汇集全部轮次，按任务替换刷新，标明对话轮次与修正次数 |
| 会话记录导出 | 保持全部轮次聊天记录 |

执行状态和确认按钮继续对应当前活动任务。后一轮批准或取消不会改写前轮确认卡片。

## 根因与实现

`beginTurn()` 原先清空事件、任务、审计和消耗；`openSession()` 回放每轮时重置消耗，最后仅保留末轮审计。现在继续提问只重置活动任务状态，新建或切换会话才清空记录。

新增 `GET /api/conversations/{conversation_id}/usage`，读取该会话全部调用；账本所有汇总查询均通过 `agent_run.conversation_id` 过滤。原有按任务和全局统计接口保留。

事件以任务 ID 和事件序号去重，避免重连重放重复计算 token。历史、详情、统计与创建任务的异步响应检查会话世代，迟到响应不会污染切换后的视图。SQL 审计面板打开时重新读取整会话账本，补齐实时刷新遗漏的轮次。

## 验证

- `check_session.py`：13 项真实前端 JavaScript 行为断言，覆盖多轮累计、重连去重、历史恢复、审计刷新、旧确认记录保留、导出轮次和迟到响应隔离。
- `check_session_usage.py`：2 项异步测试，覆盖各汇总 SQL 的会话筛选、调用归属和未知会话返回 404。
- `check_export.py`：74 项导出与产物检查通过。
- `check_usage.py`：20 项用量解析与序列化检查通过。
- `check_js.py`：前端脚本语法通过。

验证使用前端假 DOM 和后端账本替身，没有连接真实数据库或调用大模型，也未验证真实浏览器截图。本记录仅覆盖会话视图累计改造，不代表规划、SQL 生成与正常执行链路精简已全部完成。

## 手工验收

在同一会话连续问两个只读问题。第二轮结束后打开时序图、流转、消耗和审计，应能看到两轮数据；重新打开会话后范围一致。新建另一会话，上一个会话的事件和 token 不应出现。删除确认场景可在专用测试库分别取消和批准，前轮卡片决策应保持原样。

## 1. 本轮已实现

| 改造 | 行为与代码落点 |
|---|---|
| PostgreSQL AST 静态防线 | `app/sql_guard.py` 引入 pglast；拒绝写 CTE、嵌套写入、SELECT INTO、解析失败、未知函数；真实表按 PostgreSQL 标识符大小写与 CTE 作用域核对授权 |
| 固定内置函数解析 | 生成/修正阶段将允许函数限定到 pg_catalog，再展示、校验、审计；执行器拒绝未经归一的函数 SQL，避免 public 同名重载；固定参数数量的函数额外检查参数数目 |
| 执行边界复核 | executor 重新计算 SQL 风险；checks 保存 SQL hash，执行前必须匹配；SQL 改变后旧校验失效 |
| 数据库只读事务 | 只读任务调用 `BizDatabase.execute(read_only=True)`，显式事务内设置 READ ONLY；固定事务 search_path。离线验证的是适配器调用契约，未实测 PostgreSQL 权限 |
| 确认卡片绑定 | 卡片带 SQL hash 和 confirmation_version；每个按钮携带自己的绑定；接口拒绝过期版本，恢复命令传入用户提交的 hash；不再用 confirmed 布尔值跳过决定 |
| 重复请求入口保护 | start 仅接受 created，confirm 仅接受对应 confirming 版本；账本 expected_version 条件更新后才调度后台任务 |
| 准确取消终态 | 取消记录 executed=false、exec_ok=null、result.ok=false，不推进成功游标，不继续后续任务；reviewer、前端及终态恢复识别 cancelled |
| 最终门禁 | S3 检查 validated_passed；S7 只统计真实执行成功；显式保存 last_consistency，不再从 status=done 推断检查通过 |
| planner/fixer 身份 | 使用认领返回 ID；fixer 的认领、重试、结算与模型上下文统一使用新 round |
| 事实与解释分离 | 新记忆保存 truncated、sampled、interpretation、interpretation_verified；verified claim 由执行信息构造。旧 DB/旧 checkpoint 的 claim 在读取边界也不直接充当事实 |
| checkpoint 路径闭合 | 恢复模式初始化失败停止启动并关闭资源；显式关闭 checkpoint 时普通任务用 stream values 正常结束，需确认操作失败且不执行；恢复异常落 failed |

本轮解决的是第一阶段中的可验证基础修复。**不是整个第一阶段全部完成，也不是整个 Harness 协作方案已经迁移。**

## 3. 使用与兼容变化

1. 更新依赖：在项目环境运行 `python -m pip install -r requirements.txt`，新增 `pglast>=7,<8`。本轮仅为验证环境安装隔离依赖，未代替项目部署。
2. 账本 `sql/ledger.sql` 增加四个 `ADD COLUMN IF NOT EXISTS`，沿用启动迁移流程。旧数据完整性默认保守标记 true；迁移 SQL 已写入，**尚未在真实账本执行**，部署前应在隔离账本验证后应用。
3. `/api/runs/{run_id}/confirm` 现在必须传 `approve/by/version/sql_hash`。version 和 hash 必须来自当前确认卡片；旧客户端缺字段返回 422，过期版本返回 409。前端已同步更新，需要刷新页面。服务端仍采用项目现有 by 字段，未实现账户身份认证。
4. 旧 checkpoint 缺 checks.sql_hash，或包含未归一函数 SQL 时，执行器会保守拒绝；建议在升级前结束在途任务，升级后重新创建并校验，不能静默放行旧状态。
5. 函数白名单采用保守策略，未收录的正常函数也会拒绝。新增函数必须带授权与归一回归；AST 与数据库权限仍各有责任，不能宣称覆盖所有 PostgreSQL 扩展能力。

离线回归可在安装依赖后，从 sql-agent 目录执行：

```powershell
python scripts/check_reliability.py
python scripts/check_guard.py
python scripts/check_router.py
python scripts/check_prompts.py
python scripts/check_usage.py
python scripts/check_export.py
python scripts/check_js.py
```

## 4. 下一批工作：持久执行协议

当前 CAS 只保护请求进入调度，不能证明每条业务 SQL 只执行一次。后台进程在 queued/resuming 时退出仍需要恢复策略；agent_task 租约与结算还没有 owner/version fencing；业务 SQL 提交和账本写入仍在不同数据库。

下一批应先完成：

1. task/activation 句柄与 worker owner、租约续期、过期接管、结算条件、零行更新冲突处理。
2. SQL 操作标识及业务库内事务幂等记录；区分 pending/committed/unknown，提交结果未知时先对账。需要显式业务库初始化/迁移，不能借服务启动偷偷修改业务表。
3. 可销毁 PostgreSQL 测试夹具：重复请求、两个 worker 抢占、旧 worker 迟到结算、提交后落账前退出，分别验证。
4. 固定计划版本、目录快照、完整依赖门禁，限制不完整实体集合进入写操作。然后再启动无副作用分析任务的并行试点。

本轮未修复 G10 的跨任务/非连续停滞判定、G11 的完整 DAG 门禁、G12 的并行共享状态与 G14 的未知 usage 表达；它们保留为下一轮可定位任务。事务幂等、worker 接管、真实 DB 集成验证属于剩余必需工作，不应把本轮绿色离线测试当作替代。

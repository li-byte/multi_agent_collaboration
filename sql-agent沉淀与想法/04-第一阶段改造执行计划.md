# 第一阶段改造执行计划

用户已要求开始推动改造；依据 03 中第一阶段要求，在当前工作区执行并保留改造证据。

目标：先消除已复现的 P0 路径，再逐步建立持久执行排他与恢复能力。沿用 Python / LangGraph / PostgreSQL 架构。

本轮任务顺序：

- [x] 新增离线回归脚本，先观察失败：写 CTE、损坏校验历史、失败覆盖、取消、planner/fixer 结算身份、记忆完整性、无 checkpoint。
- [x] SQL 静态防线引入 PostgreSQL AST，递归识别写 CTE、SELECT INTO、未知语法；首版拒绝嵌套写入。只读执行事务设置 READ ONLY。
- [x] 取消不再伪造执行成功，一致性覆盖和 handoff 的已完成集合只认可真实成功；模型摘要与数据库证据分开。
- [x] planner/fixer 身份从认领返回值取得，fixer 使用本次 round，重试沿用相同上下文；防止错误结算。
- [x] checkpoint 初始化失败停止启动；显式无 checkpoint 模式允许普通运行、拒绝确认暂停，结束读取使用本轮最终状态。
- [x] 重跑回归及现有离线检查，记录实际范围与未覆盖的真实数据库场景。
- [x] 审查追加：双引号表精确授权、内置函数固定 pg_catalog、校验 SQL hash、确认卡片版本与 SQL hash 绑定、重复 start/confirm 条件更新、旧记忆读取降级。

后续独立迭代：持久 worker ownership/租约、确认绑定 catalog/计划版本、业务库事务幂等、fencing token、计划版本与完整依赖 DAG；这些需要真实隔离库的竞争和提交故障测试，不能由本轮离线检查宣称完成。

验收：新回归绿灯，原有检查不回退，数据库与模型替身外无业务副作用。当前历史探针作为改造前证据保留，不修改其 GAP 断言为通过。

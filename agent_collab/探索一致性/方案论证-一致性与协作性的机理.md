# 方案论证 · 多智能体的一致性与协作性机理

| 项目 | 说明 |
|---|---|
| 文档定位 | **论证方案本体**：要达到"多个智能体解决同一件事且结果一致"的效果，需要什么、为什么需要。**不涉及具体技术实现** |
| 论证对象 | 多智能体协作中的**事情一致性**与**智能体协作性** |
| 论证方法 | 效果定义 → 失效模式 → 所需机制 → 必要性论证 → 边界 → 验收判据 |
| 与实现稿的关系 | 本文是主线；`方案设计-通用协作底座-v2.md` 降级为**实现候选**（承载方式之一），待本文机制论证通过后再评估 |

---

## 0. 重新锚定问题

**要沉淀的不是"某个框架/中间件怎么实现"，而是：多个智能体围绕同一件事分工时，怎么保证这件事本身是一致的、它们之间的协作是有序的。**

- 不是"每个智能体各自正确"，而是**同一件事只有一份事实、一个状态、一个对外结论**。
- 不是"大家都连上同一个消息总线"，而是**大家依据同一份事实、遵守同一套交接规矩**。
- 技术载体（编排器、中间件、数据库）属于**实现选项**，换个承载就该重写；本文件讨论的机理则不应随载体变化。

---

## 1. 效果定义：一致性与协作性各是什么

不定义清楚就无法论证——**不同层的一致性，成本差一个数量级**。

### 1.1 事情的一致性（4 层，从便宜到贵）

| 层 | 含义 | 达不到会怎样 |
|---|---|---|
| ① 事实一致 | 所有智能体依据同一份事实（同版本、同来源） | A 用 v1 推理、B 用 v2 推理，各自都对，结论打架 |
| ② 状态一致 | "这件事进行到哪、谁在做、做完没有"只有一个答案 | 两个智能体都以为自己在做同一件事 |
| ③ 结论一致 | 判断冲突时有确定的收敛路径，对外只有一个答案 | 两个结论并存，最后谁嗓门大听谁的 |
| ④ 过程一致 | 事后能重建"发生了什么、凭什么"，换个时间看解释不变 | 出了分歧只能靠回忆复盘 |

### 1.2 智能体之间的协作性（3 层）

| 层 | 含义 | 达不到会怎样 |
|---|---|---|
| ① 不重复 | 同一件事不会同时被两个智能体做 | 白做工，甚至重复改变外部世界 |
| ② 不遗漏 | 该做的有人做、做完的有人接，交接不断链 | 链子断在中间，没人发现 |
| ③ 可接续 | 任何环节中断，接手者不用重新问一遍 | 每次重跑都从头来过 |

### 1.3 为什么要用多智能体（以及代价）

多智能体的价值在**分工**与**对抗**（不同视角互相挑错）；代价正是上面这 7 层风险。分工越细、对抗越强，不一致的概率越高。

> **推论**：一致性机制的强度必须与分工强度匹配。不是"越强越好"，而是"够用且付得起"。

## 2. 论证第一步：一致性不会自己出现——9 种失效模式

先证伪再立论。只要承认智能体是**各自独立、概率性、会被重跑**的，下面这些失效必然发生：

| # | 失效模式 | 典型表现 |
|---|---|---|
| F1 | **事实分裂** | 每个智能体各存一份事实，都"正确"，版本不同 |
| F2 | **假设污染** | 未验证的推断当结论用，进入证据链，下游继续往上盖楼 |
| F3 | **重复做功** | 重复派发 / 重跑 / 两个执行者都以为该自己做 |
| F4 | **交接断链** | 上游做完没人通知，或下游没等到就跑了 |
| F5 | **冲突无收敛** | 两个结论并存，没有规则决定听谁的 |
| F6 | **完成无判据** | 都认为做完了，但没人能证明真做完了 |
| F7 | **副作用重复** | 外部世界（发布、扣款、改配置）被动了两次 |
| F8 | **中断失忆** | 崩了之后不知道那一步做没做完，重跑 = 重复做功 |
| F9 | **事后说不清** | 无法回答"这条结论依据哪一版事实、谁给的" |

**关键判断**：F1~F9 中**没有一条能靠"让智能体自己注意点"解决**——理由见第 4 节。

---

## 3. 论证第二步：要达到效果，需要 8 个机制

### 3.1 总览

| 机制 | 治哪些失效 | 缺了会退化成什么 | 生效时的观察点 |
|---|---|---|---|
| **M1 单一事实源 + 事实版本化** | F1、F2 | 退化成"共享一段文本"，照样各读各的版本 | 任一结论都能追到"哪一版事实、谁什么时候写的" |
| **M2 事情的唯一身份 + 认领** | F3 | 退化成"谁先跑谁做"，重跑即双跑 | 同一件事任一时刻只有一个执行者 |
| **M3 结构化交接契约** | F4、F9 | 退化成"把上下文全塞给下一个"，信息过载且不可校验 | 接手者不必重新问一遍就能开工 |
| **M4 结论收敛规则** | F5 | 退化成"最后一个说话的人赢" | 冲突有确定出路，分歧被记录而非被抹掉 |
| **M5 完成判据前置** | F6 | 退化成"看起来差不多了" | 完成与否不需要争论，可以判定 |
| **M6 副作用账本 + 唯一标识** | F7 | 退化成"日志里翻一翻"，防不住第二次 | 同一动作不会被做两次，"做没做过"可查 |
| **M7 步骤两态留痕** | F8 | 退化成"崩了就整体重来" | 中断后既不重复做功，也不丢已完成部分 |
| **M8 全过程留痕可回放** | F9 | 退化成有日志但拼不出因果 | 事后能重建完整解释，且重建结果稳定 |

一句话概括：给多智能体一本**共同的账本**（M1 / M6 / M7 / M8）和一套**共同的规矩**（M2 / M3 / M4 / M5）。账本管"唯一与可追溯"，规矩管"有序与有出路"。

### 3.2 逐条展开

**M1 单一事实源 + 事实版本化**
- 为什么：事实分裂的根因不是"没有共享"，而是"共享的东西没有版本与来源"——两个智能体可能都读了同一份文件的不同时刻。
- 要求：① 事实只有一个写入点；② 每条事实带**来源**与**版本**；③ **假设与已验证分开存放**，下游默认只接受已验证的部分。
- 常见误用：用"共享上下文 / 共用一段 prompt"冒充事实共享——它既无版本也无来源，等于没有。

**M2 事情的唯一身份 + 认领**
- 为什么：多智能体最大的浪费不是做错，是**同一件事被做两遍**（重复派发、重跑、两个执行者）。
- 要求：① 每件事有**稳定身份**（重跑不变）；② "谁在做"**唯一**且**有期限**（过期可被别人接手）。
- 常见误用：用"谁先开始"隐式决定归属——重跑即双跑。

**M3 结构化交接契约**
- 为什么：智能体之间传递的应该是**工作状态**，不是聊天记录。聊天记录不可校验、不可裁剪、会越滚越大。
- 四件套：**我基于什么（事实引用）｜ 我做了什么（产出引用）｜ 我留了什么（未决/假设）｜ 你还需要什么（判据）**。
- 附加要求：能力与限制（能做什么/不能做什么）必须是**显式声明**，不能靠下游猜。
- 常见误用：把"完整上下文"当交接——信息越多，责任越模糊。

**M4 结论收敛规则**
- 为什么：多智能体的对抗价值恰恰来自分歧；但分歧必须有出路，否则退化成"谁嗓门大"。
- 要求：冲突的判断依据是**"是否基于可比的事实版本"**：可比 → 按规则收敛；**不可比 → 显式保留分歧**，不强行合并。
- 常见误用：投票 / 取最新 / 取高置信度——这些在事实版本不可比时都是假的收敛。

**M5 完成判据前置**
- 为什么："做完了没有"是争议最多、最晚讨论、也最该提前定的一件事。
- 要求：开始前就写死**可判定的完成条件**；判据不满足就不算完成，不靠"看起来差不多"。
- 常见误用：用"流程跑完了"代替"事情做成了"。

**M6 副作用账本 + 唯一标识**
- 为什么：外部世界（发布、扣款、改配置）**不能撤销**，重复执行是唯一不可逆的事故。
- 要求：① 每次对外改变有**唯一标识**与**明确终态**；② 结果不确定时**先对账再决定**，不允许"猜着重试"。
- 常见误用：用"重试 + 幂等由下游保证"——把责任推给了不该承担的人。

**M7 步骤两态留痕**
- 为什么：中断发生在"做了一半"时，如果只有一个"做完"的记录，就永远无法区分"没做"和"做了一半"。
- 要求：每步留**"开始过/完成了"两态**；中断后可判断这一步的真相，据此决定重做还是接续。
- 常见误用：只在成功时记录——崩溃点成为盲区。

**M8 全过程留痕可回放**
- 为什么：一致性的终极检验是"事后能不能说清"，而不是"当时有没有报错"。
- 要求：谁、何时、基于什么、做了什么决定，全部可重建；重建结果**稳定**（同样的输入得到同样的解释）。
- 常见误用：有日志但没有因果——查得到事件，拼不出链条。

### 3.3 机制之间的依赖关系

不是并排的 8 条，而是有前后依赖：

```
M2（唯一身份）
  └─ M7（两态留痕）─┐
M1（事实版本）──────┼─ M3（交接契约）─ M4（收敛规则）
                    └─ M6（副作用账本）
                          └─ M8（留痕回放，贯穿全部）
M5（完成判据）依赖 M3 的"你还需要什么"
```

**含义**：M1 与 M2 是地基；M5 与 M8 是收口；M3/M4 建在地基上。**若地基不成立，后四条无法补救。**

## 4. 论证第三步：为什么必须由"它们共同经过的那一层"承担

这是本方案存在的唯一理由：

1. **智能体是概率性的** —— 把纪律交给它，等于要求每次采样都遵守纪律，概率上必然失守；
2. **成本随数量线性增长** —— N 个智能体各自实现一遍同样的纪律，就是 N 倍成本、N 个出错点；
3. **无法自证** —— 智能体在自己的世界里"正确"，从内部无法判断自己看到的是不是唯一版本；
4. **重跑是常态** —— 任何一次重跑都会让"自己记住"的方案失效。

**结论**：一致性不能是**每个智能体的属性**，只能是**它们之间的公共设施**。这决定了一致性方案的形态——它必须站在智能体之外、之上。

---

## 5. 论证边界：一致性不是免费的，也不是万能的

| 边界 | 说明 |
|---|---|
| **一致 ≠ 正确** | 全体可以一致地错。一致性保证"唯一、可追溯"，不保证"结论对" |
| **一致 ≠ 强一致** | 跨外部系统只能做到"可对账"，做不到"同时成功" |
| **成本分级** | 事实一致最便宜，结论一致最贵（需要收敛规则），可复现中等。**该分级就分级** |
| **收敛性不由设施保证** | 若两个智能体永远谈不拢，只能靠"判据不满足"或"人来终止"；设施只保证不糊弄 |
| **假设无法被消灭** | 只能被**隔离**（标出来 + 不进入强制链），不能被消除——这是设计选择，不是妥协 |
| **设施不能替智能体思考** | 它保证"依据唯一、过程可查、动作不重复"，不产生任何一个判断 |

## 6. 怎么算"达到了"：6 个可判定的验收问题

论证必须收口到可检验的判据（不涉技术，可直接拿去问任何实现方案）：

| # | 问题 | 对应机制 |
|---|---|---|
| 1 | 这件事在任一时刻，是否**只有一份事实、一个状态答案**？ | M1、M2 |
| 2 | 任一结论是否都能回答"**依据哪一版事实、谁在什么时候给的**"？ | M1、M3、M8 |
| 3 | 同一动作是否会因重跑 / 重派**被做两次**？能不能**检测**出来？ | M2、M6、M7 |
| 4 | 中途中断后，接手者**是否需要重新问一遍**？会不会重复做功？ | M3、M7 |
| 5 | 出现冲突时是否有**确定的收敛路径**？谈不拢的分歧是**被保留**还是被默默合并？ | M4 |
| 6 | "做完了"是否**在开始前就已定义**，且可以判定？ | M5 |

**这 6 问全答"是"，才算达到目标效果。** 它同时也是判断任何实现方案合格与否的标尺。

## 7. 概念级方案骨架

```
        ┌──────── 协作层（规矩）────────┐
        │ 事情的身份与认领       → 不重复 │
        │ 结构化交接契约         → 不断链 │
        │ 完成判据前置           → 可判定 │
        └───────────────────────────────┘
        ┌──────── 一致性层（账本）──────┐
        │ 单一事实源 + 版本 + 假设隔离   │
        │ 结论收敛规则（可比才合并）      │
        │ 全过程留痕与回放                │
        └───────────────────────────────┘
        ┌──────── 边界层（与外界）──────┐
        │ 副作用账本 + 对账（外部世界）   │
        │ 不确定时的出口（对账 / 人工）   │
        └───────────────────────────────┘
```

**方案本体 = 第 3 节的 8 个机制 + 第 6 节的 6 个判据。**

## 8. 下一步（待论证，不涉实现）

1. **逐条判定 M1~M8 的必要性**：在本场景下哪些是必须的、哪些可以砍？
2. **找更便宜的替代**：例如 M4 的收敛是否可以由"完成判据不满足"自然终止，而不需要专门的收敛规则？
3. **评估代价**：每保留一个机制，智能体的使用成本与运行成本增加多少？值不值？
4. **判定承载方式**：机制确定之后，才评估"由什么承载"——编排器 / 中间件 / 数据库只是候选，且可替换。
5. 只有前四步完成，才进入实现设计。

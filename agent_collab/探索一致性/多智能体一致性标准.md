# 多智能体一致性标准

**Multi-Agent Consistency Standard · v1.1**

> 本标准规定两件事：**协作性要求**（过程——多个执行单元如何一起把事做成）与 **一致性要求**（结果——这件事的事实、状态、结论、过程是否唯一且可追溯）。
> **协作是因，一致是果。** 只有护栏、没有引擎，一致性机制只能"记录失败"，不能"产生一致"。

---

## 摘要

多个执行单元围绕同一件事分工协作时，最危险的情况不是它们意见不同，而是**每个执行单元都在自己的世界里正确**。

本标准定义：要让「同一件事」在多个执行单元之间保持**事实一致、状态一致、结论一致、过程一致**，并让它们之间的协作**分工清晰、交互有序、相互校验、协商共识**，需要满足哪些机制要求、如何判定是否达标。

本标准**只规定"需要什么"，不规定"用什么实现"**——编排框架、中间件、数据库、消息总线均不属于本标准范围。

---

## 1. 适用范围

**适用**：多个执行单元围绕同一件事分工协作，且产出需要对外只有一个答案的系统。执行单元可以是模型驱动的智能体，也可以是自动化流程或人。

**不适用**：单一执行单元；彼此无交集、无需对齐的并行任务；明确允许各方各说各话的场景。

**要求等级用语**：

| 用语 | 含义 |
|---|---|
| **必须** | 不满足即无法达到本标准目标 |
| **应当** | 默认需满足；不满足时须给出理由并记录 |
| **可选** | 视场景启用 |

---

## 2. 术语

| 术语 | 定义 |
|---|---|
| **事** | 一个需要被完成的目标单元，具有稳定身份，可被拆分与追踪 |
| **协作** | 多个执行单元为完成同一件事而进行的**正向行为**：分工、承诺、交接、求援、校验、协商 |
| **分工** | 把一件事拆成部分并确定"谁负责哪部分" |
| **承诺** | 执行单元**接受**某项任务并对其负责（区别于"被派发"） |
| **求援** | 执行单元因缺信息、缺能力或需第二意见而主动请求他人 |
| **交叉校验** | 由独立视角复核结论，质疑与反驳被视为贡献 |
| **协商** | 分歧时先交换依据、再共同得出唯一结论的过程 |
| **可见性** | 协作者能知道「谁在做什么、做到哪、缺什么」 |
| **事实** | 被确认的客观依据。必须带**来源**与**版本** |
| **事实版本** | 同一事实的不同修订。新版本产生新标识，旧版本不被覆盖 |
| **假设** | 未被确认的推断。与事实**分开存放**，默认不进入强制证据链 |
| **交接契约** | 执行单元之间传递的结构化工作状态，非聊天记录 |
| **可比** | 两个结论所依据的事实版本集合一致或可映射，因而可以比较 |
| **收敛** | 多个结论冲突时，按既定规则得到唯一对外结论的过程 |
| **判据** | 在开始前就已确定、且可判定的完成条件 |
| **副作用** | 对外部世界的改变（发布、扣款、修改配置等），不可撤销 |
| **账本** | 记录事实、状态、动作及其依据的唯一权威记录 |
| **两态留痕** | 每个步骤同时记录「开始过」与「完成了」两种状态 |
| **回放** | 依据账本重建「谁、何时、基于什么、做了什么决定」 |

## 3. 目标效果

本标准把目标拆成**两个维度**：协作性描述**过程**，一致性描述**结果**。

### 3.1 协作性：四级（行为属性，逐级包含）

| 等级 | 名称 | 含义 | 达不到的后果 |
|---|---|---|---|
| **H1** | 分工清晰 | 每个执行单元知道自己的职责与能力边界，"谁做什么"明确 | 谁都以为别人会做，或两人做同一部分 |
| **H2** | 交互有序 | 派发—承诺—移交—求援—应答都有明确去向与回音；不重复、不遗漏、可接续 | 任务悬空、交接断链、重复做功 |
| **H3** | 相互校验 | 多方交叉验证是常规动作；质疑与反驳被当作贡献，分歧被显式提出 | 单点结论无人复核，错误直达最终结果 |
| **H4** | 协商共识 | 分歧通过交换依据协商出共同结论；不可比的分歧被保留并上报，而非压制 | 表面一致，实际两个答案并存 |

### 3.2 一致性：四级（结果属性，逐级包含）

| 等级 | 名称 | 含义 | 达不到的后果 |
|---|---|---|---|
| **C1** | 事实一致 | 所有执行单元依据同一份事实（同版本、同来源） | 一方用旧版、一方用新版，各自都对，结论打架 |
| **C2** | 状态一致 | 「进行到哪、谁在做、做完没有」只有一个答案 | 两个执行单元都以为自己在做同一件事 |
| **C3** | 结论一致 | 判断冲突时有确定的收敛路径，对外只有一个答案 | 两个结论并存，最后谁嗓门大听谁的 |
| **C4** | 过程一致 | 事后可重建全过程，换时间点看解释不变 | 出了分歧只能靠回忆复盘 |

### 3.3 两个维度的关系

```
协作性（过程）                          一致性（结果）
H1 分工清晰  ┐                        ┌  C1 事实一致
H2 交互有序  ├── 产生 ──────────────► ├  C2 状态一致
H3 相互校验  │                        ├  C3 结论一致
H4 协商共识  ┘                        └  C4 过程一致
     引擎                                    护栏
```

- **协作机制是引擎**：它让多个执行单元真正把事做成。
- **一致性机制是护栏**：它保证做成的这件事只有一份答案、可追溯、不重复。
- **只有护栏没有引擎**，一致性机制只能"记录失败"，不能"产生一致"；**只有引擎没有护栏**，协作越热闹，分歧越多、越无法收口。

### 3.4 前提认知：多执行单元的价值与代价

多执行单元的价值在**分工**与**对抗**（不同视角互相挑错）；代价正是第 4 节列出的失效风险。分工越细、对抗越强，不一致的概率越高。

> **推论**：协作机制与一致性机制的强度必须与分工强度匹配——不是越强越好，而是够用且付得起。

## 4. 失效模式

只要承认执行单元是**各自独立、具有不确定性、且会被重跑**的，下列失效必然发生。它们不因实现方式改变而消失。

### 4.1 协作失效（X 系列：过程侧）

| 编号 | 失效模式 | 典型表现 |
|---|---|---|
| **X1** | 分工不清 | 谁都以为别人会做；或两人做同一部分，无人负责收口 |
| **X2** | 承诺缺失 | 任务被"派发"了，但没人真正认领与负责；出问题找不到人 |
| **X3** | 求援无门 | 执行单元卡住了没人可问，或问了没有回音，只能自己猜 |
| **X4** | 校验缺位 | 结论由单点产出，无独立复核，错误直达结果 |
| **X5** | 协作不可见 | 不知道别人在做什么、做到哪，导致重复或撞车 |
| **X6** | 分歧被压制 | 有异议不说、或说了被搁置，用"表面一致"换取推进 |

### 4.2 一致性失效（F 系列：结果侧）

| 编号 | 失效模式 | 典型表现 |
|---|---|---|
| **F1** | 事实分裂 | 每个执行单元各存一份事实，都"正确"，版本不同 |
| **F2** | 假设污染 | 未验证的推断当结论用，进入证据链，下游继续往上盖楼 |
| **F3** | 重复做功 | 重复派发、重跑、两个执行者都以为该自己做 |
| **F4** | 交接断链 | 上游做完没人通知，或下游没等到就跑了 |
| **F5** | 冲突无收敛 | 两个结论并存，没有规则决定听谁的 |
| **F6** | 完成无判据 | 都认为做完了，但没人能证明真做完了 |
| **F7** | 副作用重复 | 外部世界被改变了两次，且不可撤销 |
| **F8** | 中断失忆 | 崩溃后不知道那一步做没做完，重跑等于重复做功 |
| **F9** | 事后说不清 | 无法回答「这条结论依据哪一版事实、谁给的」 |

### 4.3 因果链：协作失效是一致性失效的上游

| 协作失效 | 导致的一致性失效 | 机理 |
|---|---|---|
| X1 分工不清 | F3 重复做功、F4 交接断链 | 没有明确归属，就没人负责收口 |
| X2 承诺缺失 | F4 交接断链、F6 完成无判据 | 无人负责，就无人能声明"完成" |
| X3 求援无门 | **F2 假设污染** | 没人可问，只能把猜测当结论用 |
| X4 校验缺位 | F5 冲突无收敛 | 只有一个视角，就没有冲突可收敛，只有错误 |
| X5 协作不可见 | F1 事实分裂、F3 重复做功 | 看不见彼此，就各自记一份、各自做一遍 |
| X6 分歧被压制 | F5 冲突无收敛 | 分歧没被提出，问题在收口时集中爆发 |

> **推论**：多数一致性事故，根因在协作层。只加固护栏而不修引擎，问题会持续复现。

**关键判断**：以上失效中**没有任何一条能靠"让执行单元自己注意"解决**——理由见第 6 节。

## 5. 机制要求

### 5.1 总览

**一致性机制（护栏）**

| 编号 | 机制 | 要求等级 | 对应失效 |
|---|---|---|---|
| **M1** | 单一事实源 + 事实版本化 | 必须 | F1、F2 |
| **M2** | 事的唯一身份 + 认领 | 必须 | F3 |
| **M3** | 结构化交接契约 | 应当（多轮交接时升为必须） | F4、F9 |
| **M4** | 结论收敛规则 | 应当（存在多结论时升为必须） | F5 |
| **M5** | 完成判据前置 | 必须 | F6 |
| **M6** | 副作用账本 + 唯一标识 | 必须（仅当会改变外部世界） | F7 |
| **M7** | 步骤两态留痕 | 必须（仅当允许中断或重试） | F8 |
| **M8** | 全过程留痕与回放 | 应当（受审计要求时升为必须） | F9 |

**协作机制（引擎）**

| 编号 | 机制 | 要求等级 | 对应失效 |
|---|---|---|---|
| **M9** | 能力与角色声明 | 必须 | X1 |
| **M10** | 任务承诺机制（可接受、可拒绝、可让出） | 必须 | X2 |
| **M11** | 求援与应答通道 | 必须 | X3、F2 |
| **M12** | 交叉校验（对抗式复核） | 应当（关键结论处升为必须） | X4、F5 |
| **M13** | 协商与共识规则 | 应当 | X6、F5 |
| **M14** | 协作可见性 | 必须 | X5、F1、F3 |

一句话概括：给多执行单元一本**共同的账本**（M1、M6、M7、M8）、一套**共同的规矩**（M2、M3、M4、M5），以及一张**能协作的网**（M9、M10、M11、M12、M13、M14）。

### 5.2 一致性机制逐条要求

#### M1 单一事实源 + 事实版本化

- **要求**：① 事实只有一个写入点；② 每条事实必须带**来源**与**版本**；③ **假设与已验证的事实分开存放**，下游默认只接受已验证部分。
- **缺了会退化**：变成"共享一段文本"——照样各读各的版本。
- **常见误用**：用「共享上下文 / 共用提示词」冒充事实共享。它既无版本也无来源，等于没有。
- **观察点**：任一结论都能追到「哪一版事实、谁在什么时候写的」。

#### M2 事的唯一身份 + 认领

- **要求**：① 每件事有**稳定身份**（重跑不变）；② 「谁在做」**唯一**且**有期限**，过期可被他人接手。
- **缺了会退化**：变成「谁先开始谁做」，重跑即双跑。
- **常见误用**：用"先到先得"隐式决定归属。
- **观察点**：同一件事在任一时刻只有一个执行者。

#### M3 结构化交接契约

- **要求**：交接内容必须包含四件套——**我基于什么（事实引用）｜ 我做了什么（产出引用）｜ 我留了什么（假设与未决项）｜ 你还需要什么（判据）**；能力与限制必须显式声明，不得靠下游猜。
- **缺了会退化**：变成「把全部上下文塞给下一个」——信息过载且不可校验。
- **常见误用**：把完整聊天记录当交接；信息越多，责任越模糊。
- **观察点**：接手者不必重新问一遍就能开工。

#### M4 结论收敛规则

- **要求**：冲突判定的依据是**依据的事实版本是否可比**——可比则按规则收敛；**不可比则显式保留分歧**，禁止强行合并。
- **缺了会退化**：变成「最后一个说话的人赢」。
- **常见误用**：投票、取最新、取最高置信度——在事实版本不可比时，这些都是**假收敛**。
- **观察点**：冲突有确定出路，且分歧被记录而非被抹掉。

#### M5 完成判据前置

- **要求**：「什么算做完」必须在**开始前**确定，且是**可判定**的条件；判据不满足即不算完成。
- **缺了会退化**：变成「看起来差不多了」。
- **常见误用**：用「流程跑完了」代替「事情做成了」。
- **观察点**：完成与否不需要争论，可以直接判定。

#### M6 副作用账本 + 唯一标识

- **要求**：① 每次对外部世界的改变必须有**唯一标识**与**明确终态**；② 结果不确定时**先对账再决定**，禁止"猜着重试"。
- **缺了会退化**：变成「事后翻日志」，防不住第二次。
- **常见误用**：把幂等责任推给被调用的下游。
- **观察点**：同一动作不会被做两次，且「做没做过」可查。

#### M7 步骤两态留痕

- **要求**：每个步骤必须同时记录「开始过」与「完成了」两种状态；中断后可据此判断该步骤的真相。
- **缺了会退化**：变成「崩了就整体重来」。
- **常见误用**：只在成功时记录——崩溃点成为盲区。
- **观察点**：中断后接手者既不重复做功，也不丢已完成部分。

#### M8 全过程留痕与回放

- **要求**：谁、何时、基于什么、做了什么决定，必须可重建；重建结果**稳定**（相同输入得到相同解释）。
- **缺了会退化**：变成有日志但拼不出因果。
- **常见误用**：记录事件但不记录**因果与依据**。
- **观察点**：事后能重建完整解释，且解释可复现。

### 5.3 协作机制逐条要求

#### M9 能力与角色声明

- **要求**：每个执行单元必须显式声明**我能做什么 / 我不能做什么 / 我依赖什么**；分工决策必须基于这些声明，而非默认假设。
- **为什么**：协作的第一前提是知道彼此能做什么。能力不声明，分工只能靠猜。
- **缺了会退化**：变成「能者多劳」——强者全包、弱者闲置，且能力边界无人知晓。
- **常见误用**：把"模型能力"当成"角色分工"，不区分通用能力与具体职责。
- **观察点**：任一任务都能回答「为什么由它做，而不是别人」。

#### M10 任务承诺机制

- **要求**：任务**不是被派发就算完成分派**，而是必须被**接受**；接受者可以**拒绝**（能力不匹配）或**让出**（无法继续）；接受即负责，且有期限。
- **为什么**：只派发不承诺，等于把责任留在空中；出问题时无人可问。
- **缺了会退化**：变成「任务悬空」——看起来都安排了，实际没人负责。
- **常见误用**：把"已通知"当作"已认领"。
- **观察点**：每件事都有一个**明确负责且自愿接受**的执行单元。

#### M11 求援与应答通道

- **要求**：任何执行单元都可以发起求援（缺信息 / 缺能力 / 需要第二意见）；求援必须有**去向、期限与回音**，不得静默消失。
- **为什么**：**求援无门是假设污染的直接成因**——没人可问，只能把猜测当结论用。
- **缺了会退化**：变成"各猜各的"，假设悄悄进入证据链。
- **常见误用**：把"记录了一个疑问"当成"发起了求援"（没有去向与回音）。
- **观察点**：每一条求援都能查到"谁回应了、什么时候回的"。

#### M12 交叉校验（对抗式复核）

- **要求**：关键结论**应当**由至少一个**独立视角**复核；复核者的质疑与原始产出**同等记账**；复核不得由产出者自己完成。
- **为什么**：多执行单元的核心价值就是对抗性校验，若把它省略，多执行单元就只剩成本。
- **缺了会退化**：变成单点产出——没有冲突可收敛，只有错误直达结果。
- **常见误用**：把"再问一遍同一个执行单元"当成交叉校验。
- **观察点**：关键结论能回答「谁复核的、提出了什么异议、如何处理的」。

#### M13 协商与共识规则

- **要求**：分歧时**先交换依据、再协商**；禁止用压制或搁置分歧的方式换取表面一致；协商不成时**保留分歧并上报**，不得默默合并。
- **为什么**：分歧是多视角协作的正常产物，压下去它会在收口时集中爆发。
- **缺了会退化**：变成"表面一致"——对外一个答案，内部两个真相。
- **常见误用**：用"少数服从多数"或"优先级高者定"代替依据层面的协商。
- **观察点**：存在过的分歧都能查到"依据是什么、最后怎么处理的"。

#### M14 协作可见性

- **要求**：**谁在做什么、做到哪一步、还缺什么**，必须对协作者可见，并随进展更新。
- **为什么**：看不见彼此，就会各自记一份事实、各自做一遍——F1 与 F3 的源头都在这里。
- **缺了会退化**：变成"各干各的，最后合并"，合并时才发现撞车。
- **常见误用**：只在结束时汇报结果，过程中完全黑箱。
- **观察点**：任一时刻都能回答「现在有谁在做、做到哪」。

---

### 5.4 机制依赖关系

机制不是并列清单，而是有先后的结构：

```
协作引擎（产生）                          一致性护栏（收口）
M9  能力声明 ┐                          ┌ M1  单一事实源 + 版本
M14 可见性   ├─► M10 承诺 ─► M11 求援 ─►├ M2  唯一身份 + 认领
             │        └─► M12 交叉校验 ─►├ M3  交接契约
             └────────► M13 协商共识  ─►├ M4  收敛规则
                                        ├ M5  完成判据
                                        ├ M6  副作用账本
                                        ├ M7  两态留痕
                                        └ M8  留痕与回放
```

**含义**：M9 与 M14 是最下层的前提（知道自己能做什么、知道别人在做什么）；M10 ~ M13 是协作主体；M1 ~ M8 是收口与护栏。**下层不成立，上层无法补救**——例如没有 M14 可见性，M1 的单一事实源就无从建立。

---

## 6. 责任归属原则

协作纪律与一致性纪律**都不能**是每个执行单元的属性，**必须**是它们之间的公共设施。理由：

1. **不确定性** —— 把纪律交给执行单元，等于要求每次执行都遵守纪律，概率上必然失守；
2. **成本随数量增长** —— N 个执行单元各自实现一遍同样的纪律，就是 N 倍成本、N 个出错点；
3. **无法自证** —— 执行单元在自己的世界里"正确"，从内部无法判断自己看到的是否唯一版本；
4. **重跑是常态** —— 任何一次重跑都会让"自己记住"的方案失效；
5. **协作需要公共视图** —— "谁在做什么、谁需要帮忙"本质上是一个**共享视图**，个体无法自建。

**结论**：本标准的两组机制都必须由执行单元之外、之上的一层承担，而非写入每个执行单元的职责。

## 7. 边界与权衡

本标准明确不承诺以下内容，以避免空头支票：

| 边界 | 说明 |
|---|---|
| **一致 ≠ 正确** | 全体可以一致地错。本标准保证「唯一、可追溯」，不保证结论正确 |
| **一致 ≠ 强一致** | 跨外部系统只能做到「可对账」，做不到「同时成功」 |
| **协作 ≠ 一致同意** | 协作的目标是"依据充分、路径清晰"，不是"人人满意"；分歧可被保留 |
| **协作有成本** | 分工、校验、协商都要付出沟通成本；**过度协作**（无止境对齐）同样会拖垮系统，故机制强度应分级 |
| **成本分级** | 事实一致最便宜，结论一致最贵（需要收敛与协商规则），过程一致居中。该分级就分级 |
| **收敛性不由设施保证** | 若各方永远谈不拢，只能靠「判据不满足」或「人来终止」；设施只保证不糊弄 |
| **假设无法被消灭** | 只能被**隔离**（标注且不进入强制链），不能被消除——这是设计选择，不是妥协 |
| **设施不替执行单元思考** | 它保证依据唯一、过程可查、动作不重复、协作有序，但不产生任何判断 |

## 8. 验收判据

### 8.1 一致性判据（结果侧）

| 编号 | 判据 | 对应机制 |
|---|---|---|
| **A1** | 这件事在任一时刻，只有**一份事实、一个状态答案** | M1、M2 |
| **A2** | 任一结论都能回答「**依据哪一版事实、谁在什么时候给的**」 | M1、M3、M8 |
| **A3** | 同一动作不会因重跑或重派**被执行两次**，且可**检测** | M2、M6、M7 |
| **A4** | 中途中断后，接手者**无需重新问一遍**，也不重复做功 | M3、M7 |
| **A5** | 冲突有**确定的收敛路径**；不可比的分歧**被保留**而非被默默合并 | M4 |
| **A6** | 「做完了」**在开始前就已定义**，且可以判定 | M5 |

### 8.2 协作性判据（过程侧）

| 编号 | 判据 | 对应机制 |
|---|---|---|
| **A7** | 每个执行单元的**能力边界与职责**是否显式，且分工决策有据可依 | M9 |
| **A8** | 每件事是否有**明确负责且自愿接受**的执行单元，且有期限 | M10 |
| **A9** | 求援是否**有去向、有期限、有回音**，无静默消失 | M11 |
| **A10** | 关键结论是否由**独立视角**复核，质疑是否被记录与处理 | M12 |
| **A11** | 分歧是否被**显式提出并协商**，而非被压制、搁置或默默合并 | M13 |
| **A12** | 任一时刻能否回答「**现在有谁在做、做到哪、缺什么**」 | M14 |

**A1~A12 全部成立，方可判定达到本标准目标。**

## 9. 选级建议

按场景选择目标等级，再据此确定必须满足的机制（不必一开始就上全部）：

| 场景特征 | 建议目标 | 必须满足的机制 |
|---|---|---|
| 只读分析、结论仅参考 | H1 + C1 | M9、M14、M1、M2 |
| 需要对外给出唯一结论 | H3 + C3 | M9 ~ M12、M14、M1 ~ M5 |
| 会改变外部世界（发布 / 扣款 / 变更） | H4 + C3，且必须含副作用治理 | 上述 + M6、M7、M13 |
| 受审计 / 合规约束，需要事后复盘 | H4 + C4 | 全部（含 M8） |

> 逐级累加：H2 包含 H1，H3 包含 H2，H4 包含 H3；C 维度同理。

## 10. 常见反模式

| 反模式 | 问题 |
|---|---|
| 「我们共享上下文，所以事实是一致的」 | 无版本、无来源的共享不构成事实一致（违反 M1） |
| 「任务已经派出去了」 | 派发不等于承诺，无人负责收口（违反 M10） |
| 「一个人出结论，其他人点头」 | 无独立视角，错误直达结果（违反 M12） |
| 「有异议先搁置，先往下走」 | 压制分歧换取表面一致，问题在收口时爆发（违反 M13） |
| 「各干各的，最后合并」 | 过程黑箱，撞车与事实分裂不可避免（违反 M14、M1） |
| 「谁强谁全干」 | 能力不声明、不互补，多执行单元只剩成本（违反 M9） |
| 「有疑问就自己先假设一下」 | 求援没走通，假设被当结论用（违反 M11、M1） |
| 「我们记了详细日志」 | 有事件无因果、无依据，仍答不出 A2（违反 M8） |
| 「我们让每个执行单元自己保证幂等」 | 把公共纪律下放为个体责任，成本随数量增长且不可证明（违反第 6 节） |
| 「冲突时取最新 / 投票决定」 | 事实版本不可比时属假收敛（违反 M4） |
| 「流程跑完了就算完成」 | 用过程代替结果判据（违反 M5） |
| 「超时就重试」 | 对不可撤销的副作用而言，重试即事故（违反 M6） |
| 「崩了就整体重跑」 | 重复做功、重复副作用（违反 M7） |

## 11. 结语

多执行单元的一致性，本质不是"让执行单元更聪明"，而是给它们三样东西：

- **一本共同的账本**：事实与状态唯一、动作与依据可追溯；
- **一套共同的规矩**：交接不断链、冲突有出路、完成有判据；
- **一张能协作的网**：能力说得清、任务有人认、卡住有人帮、结论有人验、分歧能协商、彼此看得见。

**协作是因，一致是果。** 只有把协作的引擎装好，一致性才不是一句口号——才能说：**同一件事，同一份事实，同一套状态，任何时刻都拿得出证据。**
